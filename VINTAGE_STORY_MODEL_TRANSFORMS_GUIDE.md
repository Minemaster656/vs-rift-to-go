# Интеграция позиций модели предмета в JSON Vintage Story

Инструкция для ИИ-агента. Она описывает перенос уже подготовленных пользователем
значений положения, вращения, центра и масштаба в мод Vintage Story.

## 1. Задача агента

Когда пользователь передаёт один или несколько блоков `*Transform`, агент должен:

1. определить целевую версию Vintage Story и папку конкретного мода;
2. найти определение предмета или блока в `assets/<домен>/itemtypes/...` либо
   `assets/<домен>/blocktypes/...`;
3. определить, к какому игровому контексту относится каждый transform;
4. аккуратно объединить значения с существующим JSON, не удаляя соседние свойства;
5. проверить синтаксис и сообщить, какие положения требуют ручного теста в игре.

Не вставляй эти настройки в shape-файл из `shapes/...`. Shape содержит геометрию,
UV, элементы и их pivots. Позиции предмета в разных игровых контекстах задаются в
определении из `itemtypes` или `blocktypes`.

## 2. Куда помещать transform-блоки

| Игровая ситуация | Ключ | Уровень JSON |
|---|---|---|
| Стандартный вид от первого лица | `fpHandTransform` | корень определения |
| Предмет в руке от третьего лица | `tpHandTransform` | корень определения |
| Иконка в инвентаре и интерфейсе | `guiTransform` | корень определения |
| Выброшенный предмет-сущность | `groundTransform` | корень определения |
| Предмет поставлен на землю через `GroundStorable` | `groundStorageTransform` | внутри `attributes` |
| Предмет на полке свитков | `onscrollrackTransform` | внутри `attributes` |
| Предмет в обычной витрине/на полке | `onDisplayTransform` | обычно внутри `attributes` |
| Предмет в клещах | `onTongTransform` | обычно внутри `attributes` |
| Предмет в металлических клещах | `onMetalTongTransform` | обычно внутри `attributes` |

`groundTransform` и `groundStorageTransform` не взаимозаменяемы. Первый применяется
к выброшенному предмету, второй — к аккуратно поставленному объекту. Их масштабы
работают в разных контекстах и не обязаны быть похожими.

Для особых стоек одного transform недостаточно. Например, размещение на полке
свитков должно быть отдельно разрешено механикой предмета, часто атрибутом
`scrollrackable`. Transform только располагает уже допущенный предмет.

## 3. Значение полей

Стандартный блок выглядит так:

```json
"guiTransform": {
  "translation": { "x": 0, "y": 0, "z": 0 },
  "rotation": { "x": 0, "y": 0, "z": 0 },
  "origin": { "x": 0.5, "y": 0.5, "z": 0.5 },
  "scale": 1
}
```

- `translation` — локальное смещение модели по трём осям;
- `rotation` — поворот в градусах;
- `origin` — центр, относительно которого применяются поворот и масштаб;
- `scale` — равномерный масштаб.

Не инвертируй знаки и не пересчитывай значения по собственному предположению.
Направления осей могут ощущаться по-разному в интерфейсе, руке, клещах и на земле.
Если пользователь получил числа через игровой Transform Editor, переноси их
буквально, а последующую калибровку выполняй по результатам скриншота из того же
контекста.

## 4. Правильное объединение с существующим JSON

Корневые transform-блоки добавляются рядом с `shape`, `textures`, `attributes`,
`creativeinventory` и другими корневыми полями:

```json
{
  "code": "exampleitem",
  "shape": { "base": "item/exampleitem" },

  "fpHandTransform": {
    "translation": { "x": 0, "y": 0, "z": 0 },
    "rotation": { "x": 0, "y": 0, "z": 0 },
    "origin": { "x": 0.5, "y": 0.5, "z": 0.5 },
    "scale": 1
  },

  "tpHandTransform": {
    "translation": { "x": 0, "y": 0, "z": 0 },
    "rotation": { "x": 0, "y": 0, "z": 0 },
    "scale": 1
  },

  "guiTransform": {
    "rotation": { "x": -30, "y": -45, "z": 0 },
    "origin": { "x": 0.5, "y": 0.5, "z": 0.5 },
    "scale": 1.5
  },

  "groundTransform": {
    "translation": { "x": 0, "y": 0, "z": 0 },
    "rotation": { "x": 0, "y": 0, "z": 0 },
    "scale": 1
  },

  "attributes": {
    "existingAttribute": true,
    "groundStorageTransform": {
      "translation": { "x": 0, "y": 0, "z": 0 },
      "rotation": { "x": 0, "y": 0, "z": 0 },
      "origin": { "x": 0.5, "y": 0, "z": 0.5 },
      "scale": 1
    }
  }
}
```

Если `attributes` уже существует, добавляй новое поле внутрь него. Не создавай
второй объект `attributes` и не заменяй весь существующий объект: так можно случайно
удалить вместимость, поведение еды, параметры горения или другие механики.

Если конкретный transform уже существует, замени только его содержимое. Перед
изменением сохрани все поля, которые пользователь не просил менять.

## 5. Преобразование присланного YAML-подобного фрагмента

Пользователь может прислать результат в удобной записи без кавычек:

```yaml
groundTransform: {
  translation: { x: 0, y: 0, z: 0 },
  rotation: { x: -86, y: 0, z: 0 },
  origin: { x: 0.5, y: 0, z: 0.43 },
  scale: 3.42
}
```

В строгом JSON определения это должно стать:

```json
"groundTransform": {
  "translation": { "x": 0, "y": 0, "z": 0 },
  "rotation": { "x": -86, "y": 0, "z": 0 },
  "origin": { "x": 0.5, "y": 0, "z": 0.43 },
  "scale": 3.42
}
```

Добавь запятую между соседними свойствами объекта, но не оставляй лишнюю запятую,
если проект требует строгий JSON. Не превращай десятичную точку в запятую.

Если пользователь прислал оболочку вида `attributes: { ... }`, перенеси только её
дочерние поля в уже существующий `attributes`, если такой объект есть.

## 6. Сначала выясни, какой файл реально загружается

Перед правкой проверь:

- домен и код предмета;
- находится ли объект в `itemtypes` или `blocktypes`;
- нет ли нескольких вариантов с одинаковым назначением;
- не создаётся ли объект через JSON patch;
- копирует ли проект изменённые ассеты в Release-каталог;
- не тестирует ли пользователь старый ZIP с тем же номером версии.

Редактирование файла в `bin` не считается исходной правкой. Изменяй authored-файл
в папке проекта, затем собирай или копируй его штатным способом проекта.

Для variant-объекта общий transform обычно задаётся один раз в определении и
применяется ко всем вариантам. Делай отдельные значения по типам только при наличии
реальной необходимости и проверенного формата целевой версии игры.

## 7. Особый случай: собственный renderer

Если мод вручную задаёт `renderinfo.ModelRef`, это само по себе обычно меняет mesh,
а не обязательно отменяет стандартный transform предмета. Но код также может
перезаписывать `renderinfo.Transform` или полностью рисовать модель отдельным
рендерером. В таком случае JSON-позиция может применяться частично либо вообще не
использоваться.

Перед выводом «transform не работает» найди в C#:

- `OnBeforeRender`;
- присваивания `renderinfo.Transform`;
- собственные реализации `IRenderer`;
- ручные матрицы `Translate`, `Rotate` и `Scale`.

Не добавляй второе смещение в код, пока не установлено, что стандартный transform
действительно обходится.

## 8. Проверка после интеграции

Агент должен выполнить доступные неигровые проверки:

1. JSON успешно разбирается;
2. каждый ключ встречается на правильном уровне и не продублирован;
3. `shape.base` продолжает ссылаться на существующую форму;
4. существующие `attributes`, варианты, поведения и текстуры сохранены;
5. изменённый authored-файл попал в Release-вывод или архив;
6. архив содержит `modinfo.json` в ожидаемом корне и не содержит лишнюю внешнюю
   папку вокруг мода.

Игровую позицию нельзя объявлять проверенной только по JSON. Пользователь должен
посмотреть каждый затронутый контекст отдельно:

- первое лицо;
- третье лицо, желательно также F5 сверху и сбоку;
- иконка инвентаря;
- выброшенный предмет;
- наземное хранение;
- специальная стойка или клещи, если они поддерживаются.

После теста проси назвать не только направление ошибки, но и контекст: «правее в
иконке» не означает то же самое изменение оси, что «правее в клещах».

## 9. Основные запреты и ловушки

- Не двигай всю геометрию shape-файла ради настройки одной игровой позиции.
- Не меняй pivots анимационной модели ради иконки или выброшенного предмета.
- Не считай положение ванильной модели универсальным эталоном: сама геометрия может
  быть заранее смещена относительно начала координат.
- Не переносись слепо между `groundTransform` и `groundStorageTransform`.
- Не заменяй весь `attributes` одним новым transform-блоком.
- Не обещай, что transform добавляет поддержку полки, клещей или GroundStorable:
  для этого нужны соответствующие механики.
- Не калибруй несколько контекстов одной догадкой. У каждого своя матрица и оси.
- Не правь ванильные файлы игры. Используй их только как версионно подходящие
  примеры для ассетов мода.

## 10. Формат отчёта пользователю

После работы сообщи:

- какой authored-файл изменён;
- какие transform-блоки добавлены или заменены;
- какие соседние свойства сохранены;
- прошли ли JSON и сборка;
- куда создан архив, если он был запрошен;
- какие позиции ещё должен проверить пользователь вручную.

Не называй визуальное положение исправленным до игрового подтверждения.
